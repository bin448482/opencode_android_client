# 文件浏览路径复制需求

## 背景

文件页的目录和文件条目当前只能短按进入目录或打开预览，用户无法复制路径或文件名，导致无法在聊天输入框、终端或其他应用中复用工作区路径。

## 目标

用户可以从文件浏览页复制目录或文件的完整相对路径。

## 交互需求

1. 文件浏览列表中的每个目录和文件条目均支持长按。
2. 长按条目时，将该条目的完整相对路径复制到系统剪贴板。路径以服务端返回的 `FileNode.path` 为准，例如 `app/src/main/java/com/example/MainActivity.kt`。
3. 长按目录条目复制目录路径；长按文件条目复制文件路径。
4. 复制成功后，界面显示短暂反馈，明确告知用户路径已复制。
5. 短按目录仍进入该目录；短按文件仍打开文件预览。复制功能不得改变现有短按行为。
6. 文件列表顶部显示的当前目录路径应支持长按复制；根目录标题“文件”不需要复制功能。

## 非目标

- 不新增文件重命名、移动、删除或分享能力。
- 不提供文件内容复制；文件内容的选择和复制不属于本需求。
- 不改变服务端文件树、文件状态或文件预览接口。

## 验收标准

1. 长按任意文件条目后，系统剪贴板内容与其 `FileNode.path` 完全一致。
2. 长按任意目录条目后，系统剪贴板内容与其 `FileNode.path` 完全一致，且不会进入该目录。
3. 长按非根目录的顶部当前路径后，系统剪贴板内容与当前路径完全一致。
4. 每次成功复制均有用户可见的确认反馈。
5. 短按文件和目录的既有行为保持不变。
